# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"CCA – Customer Contact API": a prototype REST API built with Symfony 8.1, API Platform 5.0 (`api-platform/core ^5.0`), Doctrine ORM 3 (DBAL 4, DoctrineBundle 3), MySQL 8 and PHPUnit 12. There is no frontend and no login; authentication is token-only. The branch `upgrade/docker-symfony-8` is meant for a Docker setup and an upgrade to Symfony 8; the Docker setup now exists.

## Goals and conventions

- **Goal:** upgrade to Symfony 8.1 and API Platform 5, then add Messenger with RabbitMQ, voters and a CI pipeline.
- **Upgrade path:** API Platform 4.4 requires Symfony `^7.4 || ^8.0` (checked with `composer why-not`), so the order is: Symfony 7.0 → 7.4 (done), then API Platform 3.2 → 4.4 (done, including the filters: `Customer` now uses `QueryParameter` with `PartialSearchFilter`, `ExactFilter` and `SortFilter` instead of the deprecated `#[ApiFilter]`, `SearchFilter` and `OrderFilter`), then API Platform 4.4 → 5.0 (done: validation type errors now return `422` `ConstraintViolation` instead of `400`; tests use `ApiPlatform\Test\ApiTestCase`), then PHPUnit 12 and the Doctrine/Monolog bundles (still on Symfony 7.4), then Symfony 8.1 (done). The characterization tests for the `Customer` filters and ordering (`CustomerFilterTest`) stayed green when the filters were replaced; keep them green.
- **Planned design decisions (not implemented yet, decide in the test/voter step):**
  - Country → City and City → Address: no cascade delete. Refuse to delete a parent that still has children (`409 Conflict`; the DB foreign keys already have no `ON DELETE CASCADE`). Today `orphanRemoval: true` implies `cascade: remove`, so deleting a Country removes its Cities and Addresses.
  - Customer: never hard-delete (traceability, analysis). Soft delete or a status field, plus anonymisation on request (GDPR right to erasure). Mind the unique `email` constraint.
  - Keep cascade only where the child is part of the parent: `User` → `ApiToken`.
  - First add a test that pins the current cascade behaviour, then change it on purpose.
- **Authentication:** custom `ApiTokenAuthenticator` with the `x-api-key` request header (the README wrongly says `api`; fix the README later).
- **Schema changes** only via Doctrine migrations.
- **Configuration:** prefer PHP attributes over YAML.

## Setup and commands

The app runs in Docker (`Dockerfile`, `compose.yaml`: FrankenPHP + PHP 8.4, MySQL 8.0.36, project name `cca`); the host has PHP 7.4, so run all commands with `docker compose exec web ...`. Web: http://localhost:8080, MySQL on the host: `127.0.0.1:3307`. `.env` and `.env.test` are committed with safe defaults only (secrets go to `.env.local`, which is ignored). In test, Doctrine appends `_test` to the DB name (`config/packages/doctrine.yaml`); the `cca` DB user may use all `cca%` databases (`docker/mysql/init.sql`). `composer recipes:update <package>` needs git (installed in the image) and a clean git index, so commit after each recipe; keep project-specific config (`app_user_provider`, `request_log`, MySQL `DATABASE_URL`) when a recipe conflicts. `config/reference.php` is generated by Symfony in debug mode and is committed; PHPStan skips it.

```bash
docker compose up -d --build                                # API docs: http://localhost:8080/api
docker compose exec web composer install
docker compose exec web php bin/console doctrine:migrations:migrate -n           # dev DB
docker compose exec web php bin/console --env=test doctrine:database:create
docker compose exec web php bin/console --env=test doctrine:migrations:migrate -n  # test DB

docker compose exec web php bin/phpunit                     # all tests
docker compose exec web php bin/phpunit tests/CityTest.php  # one file
docker compose exec web php bin/phpunit --filter testCreateCitySuccess  # one test
docker compose exec web vendor/bin/phpstan analyse --memory-limit=1G  # level 6, config phpstan.dist.neon (128M is too little)
```

`phpunit.xml.dist` sets `failOnDeprecation="true"` and `<source ignoreIndirectDeprecations="true">` (with `src` and `tests` as first-party code): a deprecation triggered by our code (self) or by our call of a deprecated vendor method or property (direct) fails the run; indirect ones from `vendor/` are ignored. `<deprecationTrigger>` (`trigger_deprecation()` and Doctrine's `Deprecation::trigger()`) is required: without it a deprecated vendor call is not reported at all (checked with a throwaway test). Known gaps (same test): extending a vendor class marked `@final` and loading a deprecated vendor class are classified as indirect and do not fail the run. `symfony/phpunit-bridge` was removed: it made no difference to the result of these checks. Code style: PHP CS Fixer with `@Symfony` (`.php-cs-fixer.dist.php`; `yoda_style` is switched off on purpose); check with `docker compose exec web vendor/bin/php-cs-fixer fix --dry-run --diff`, fix by running it without `--dry-run`. CI: `.github/workflows/ci.yml` (PHP CS Fixer, PHPStan, migrations, PHPUnit).

## Architecture

- **Resources = Doctrine entities.** All API resources are defined with `#[ApiResource]` directly on `src/Entity/*` (no DTOs, no custom state providers/processors, no controllers). `src/ApiResource/` and `src/Controller/` are empty.
- **Domain model:** `Country` 1–n `City` 1–n `Address` n–1 `Customer`; `User` 1–n `ApiToken`. Deletes cascade through `orphanRemoval`/`cascade: ['remove']` (deleting a Country removes its Cities and their Addresses). `Customer` persists Addresses via `cascade: ['persist']` and accepts nested address writes (denormalization groups `customer:write` + `address:write`). Serialization uses `<entity>:read` / `<entity>:write` groups (attributes from `Symfony\Component\Serializer\Attribute`; the `Annotation` aliases were removed in Symfony 8).
- **Access control** lives in `#[ApiResource(security: ...)]`: `ROLE_USER` for customers, addresses, cities, countries; `ROLE_ADMIN` for `users` and `api_tokens`. `access_control` in `security.yaml` is empty.
- **Authentication:** `src/Security/ApiTokenAuthenticator.php` is the `custom_authenticator` of the `main` firewall. It reads the `x-api-key` header (the README wrongly says `api`), looks up the user via `UserRepository::findByApiToken()` (→ `ApiTokenRepository`), and returns a `SelfValidatingPassport`. Failure returns a JSON 401. Tokens are created manually: `php generate-token.php` prints a random token that is inserted into the `api_token` table.
- **API Platform config** (`config/packages/api_platform.yaml`): only JSON-LD (`application/ld+json`); PATCH needs `application/merge-patch+json`. `standard_put: false`, `serializer.hydra_prefix: true` (API Platform 4+ turns the `hydra:` prefix off by default; it is kept for existing clients). `keep_legacy_inflector` and `event_listeners_backward_compatibility_layer` were removed in 4.x. `PUT` is not a default operation in API Platform 4, so `City`, `Country` and `Customer` list their operations explicitly (like `Address`).
- **Customer filters** are `QueryParameter`s in `#[ApiResource(parameters: ...)]`: `name` and `email` use `PartialSearchFilter` (case-insensitive by default: `LOWER(field) LIKE LOWER(:value)`), `address.city.name` uses `ExactFilter`, `order[name]` uses `SortFilter` (`properties: ['name']`; other fields are ignored). `ExactFilter` has no case option, so the case-insensitive city search depends on the MySQL collation; `CustomerFilterTest` pins it.
- **Request logging:** `src/EventListener/LogRequestAndResponseEventListener.php` listens to `kernel.terminate` and logs to the `request_log` Monolog channel (tagged in `config/services.yaml`). The handler exists only in `when@dev` and writes to `var/log/request/`.
- **Timestamps:** `Customer` sets `createdAt`/`updatedAt` with `#[ORM\HasLifecycleCallbacks]` (`stof/doctrine-extensions-bundle` is required but not registered in `bundles.php`).

## Tests

- Functional API tests in `tests/` (`CityTest`, `CountryTest`, `CustomerFilterTest`) extend API Platform's `ApiTestCase` and need a real MySQL test database.
- Each test loads fixtures with Liip `DatabaseToolCollection` (`UserFixtures`, `CountryFixtures`, `CityFixtures`, `CustomerFixtures` in `src/DataFixtures/`; fake data only); this resets the DB per test. `dama/doctrine-test-bundle` is required but not enabled.
- `UserFixtures` creates `test@example.com` (`ROLE_USER`) with a fixed API token; tests read it back and send it as `x-api-key`.
- Tests assert Hydra keys (`hydra:member`, `hydra:totalItems`, `hydra:Error`) and the media type `application/ld+json` (API Platform 4 sends no `charset`). The keys depend on `serializer.hydra_prefix: true`; check them again when upgrading API Platform.
- Test classes set `protected static ?bool $alwaysBootKernel = true;` (API Platform stops booting the kernel by default).
